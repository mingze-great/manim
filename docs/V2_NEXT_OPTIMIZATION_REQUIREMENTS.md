# V2 Next Optimization Requirements

## Baseline

- Base branch: `feature/v2-ui-mobile-ux-recover-3003`
- Working branch: `feature/v2-next-optimization`
- Worktree: `E:\ai\wt_v2_next_optimization`

## Goal

基于当前 `v2.0` 基线，对新版前端与后台体验做一轮交互和管理能力优化，重点覆盖：

1. 对话页交互美化
2. 无效 UI 清理
3. 移动端后台可用性
4. 注册/登录与密码能力
5. 首页/工作台双向导航
6. 用户版本与每日限额批量管理
7. 脚本生成过程中的术语去技术化
8. PC 端页面取消左右滑动依赖

---

## Requirement List

### 1. 对话页面“对话风格”选择框样式优化

现状：
- 页面：`frontend/src/pages/ProjectChat.tsx`
- 当前存在风格说明提示，但选择控件视觉较弱，与页面整体风格不统一。

需求：
- 优化“对话风格”选择区域的视觉层级与控件样式。
- 提升可读性、点击面积和移动端体验。
- 保持现有风格参数传递逻辑不变。

验收标准：
- 风格区域整体更清晰。
- 移动端点击不拥挤。
- 不影响 `style_code` 传参。

---

### 2. 移除右下角铃铛提示按钮

现状：
- 文件：`frontend/src/components/Layout/MainLayout.tsx`
- 存在 `BellOutlined` 的 `FloatButton`，固定显示 `badge={{ count: 3 }}`。
- 没有实际消息能力。

需求：
- 删除该铃铛按钮及相关无用样式。

验收标准：
- 页面不再出现该铃铛浮动按钮。
- 不影响其他布局。

### 3. 移动端管理员增加明显的“回到后台管理”入口

现状：
- 文件：`frontend/src/components/Layout/AdminLayout.tsx`
- 桌面端已有后台首页入口，但移动端路径不够明显。

需求：
- 在移动端后台中增加明确的“后台首页”或“回到后台管理”入口。

验收标准：
- 移动端管理员在任意后台页都能方便返回后台主入口。

### 4. 注册改为“用户名 + 手机号 + 密码”，去掉邮箱；用户名支持随机生成后修改

现状：
- 前端：`frontend/src/pages/Register.tsx`
- 前端服务：`frontend/src/services/auth.ts`
- 后端：`backend/app/api/auth.py`
- 用户 schema：`backend/app/schemas/user.py`
- 用户模型：`backend/app/models/user.py`
- 当前注册依赖 `username + email + password`

需求：
- 注册不再要求用户输入邮箱。
- 增加手机号字段。
- 用户名支持随机生成，同时允许手动修改。

待确认：
- 手机号是否必须唯一。
- 邮箱是彻底废弃还是改为系统内部占位。
- 随机用户名命名规则。

验收标准：
- 注册页表单改为用户名、手机号、密码。
- 支持一键随机生成用户名。
- 用户仍可手动修改用户名。

风险：
- 涉及数据库字段与注册流程变更，属于高风险项。

### 5. 登录后支持修改密码

现状：
- 目前普通用户没有自助修改密码能力。
- 管理员后台仅支持重置他人密码。

需求：
- 为普通用户提供修改密码能力。
- 优先考虑放在个人中心中完成。

待确认：
- 是仅支持“登录后修改密码”，还是也要“忘记密码”。

验收标准：
- 用户登录后可在个人中心完成密码修改。
- 后端校验旧密码。
- 修改成功后有明确提示。

### 7. 移动端用户管理支持设置新老版本；同时支持批量设置版本

现状：
- 文件：`frontend/src/pages/admin/AdminUsers.tsx`
- 桌面表格版已有单用户 `frontend_version` 切换。
- 移动端卡片版仅展示版本标签，没有切换能力。
- 后端当前仅有单用户版本更新接口，没有批量版本更新接口。

需求：

- 支持批量设置用户前端版本。

验收标准：
- 移动端卡片上可以单独切换用户版本。
- 支持批量把选中用户切换到 `legacy` 或 `v2`。
- 管理员账号按现有规则处理。

### 8. 每日思维可视化限额更新逻辑排查并支持批量设置每日限额

现状：
- 页面：`frontend/src/pages/admin/AdminUsers.tsx`
- 当前单用户有“配额”设置能力。
- 但 UI 展示同时依赖：
  - `daily_video_limit`
  - `module_permissions.visual.daily_limit`
- 可能存在展示值和实际生效值不同步的问题。

需求：
- 彻底排查“每日思维可视化限额”的真源字段。
- 修复单用户更新后显示/生效不一致问题。
- 增加批量设置每日限额能力。

验收标准：
- 单用户更新后，展示值与实际生效一致。
- 支持对选中用户批量设置每日思维可视化限额。
- 管理员账号处理规则明确。

风险：
- 涉及配额真源统一，属于中高风险项。

### 9. 脚本生成过程中的“代码”术语全部去掉

新增需求。

现状：
- 脚本生成相关页面与流程中，仍可能出现“代码”两个字。
- 这与当前产品对外表达不一致，会增加技术感和理解成本。

需求：
- 在“脚本生成”相关用户流程中，避免出现“代码”字样。
- 对用户可见文案统一使用：
  - `脚本`
  - `内容`
  - `视频内容`
  - `生成结果`
  等更自然表述。

范围：
- 脚本生成页
- 对话页相关提示
- 生成进度提示
- 错误提示
- 任何用户可见按钮、标签、说明文本

不要求：
- 内部接口名、内部变量名、后端方法名不必全部改动
- 本次重点是“用户可见文案”去掉“代码”字样

验收标准：
- 用户在脚本生成相关流程中，不再看到“代码”两字。
- 仅保留内部实现层面的 `code` 命名，不暴露给用户。

### 10. PC 端相关页面取消左右滑动依赖

新增需求。

范围：

- `ProjectTask`（脚本生成页）
- `AdminUsers`（用户管理）
- `AdminTemplates`（代码模板）
- `AdminChatStyles`（对话风格）

现状：
- 用户管理页面 PC 端当前使用 `Table`，并显式依赖 `scroll={{ x: 800 }}`。
- 代码模板页面 PC 端当前使用 `Table`，并显式依赖 `scroll={{ x: 1000 }}`。
- 脚本生成页当前模板展示更偏横向卡片浏览体验，PC 端可能形成横向浏览/滑动依赖。
- 对话风格页面虽然当前未显式设置横向滚动，但整体仍是传统表格承载方式，桌面端信息组织仍可进一步优化，避免横向感和拥挤感。

需求：
- PC 端以上页面不依赖左右滑动完成主要操作。
- 优先通过布局重组、字段压缩、信息分组、展开详情、卡片/表格混合结构来解决信息密度问题。
- 移动端现有优化不能退化。

建议实现方向：

1. `ProjectTask`
- 将 PC 端模板展示改为固定列数网格或更稳定的卡片栅格。
- 不再默认使用横向卡片流作为主要展示方式。

2. `AdminUsers`
- 重构 PC 端表格列，减少横向滚动依赖。
- 将版本、配额、权限、操作区压缩并分层展示。
- 必要时引入展开行或详情抽屉承载次级信息。

3. `AdminTemplates`
- 不再使用超宽表格承载全部信息。
- 可采用表格主列 + 展开详情，或桌面卡片列表方案。

4. `AdminChatStyles`
- 优化 PC 端布局，不再维持拥挤的表格式横向感。
- 可以考虑桌面端也改成卡片列表，与移动端保持更统一的视觉语言。

验收标准：
- 常见 PC 宽度下，无需左右拖动即可完成主要操作。
- 主要按钮、版本切换、配额信息、模板操作等始终可见。
- 页面信息层级更清晰。
- 移动端现有优化不退化。
