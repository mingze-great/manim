# 质量门禁

## 目的
质量门禁用于把“能跑”变成“可控、可复现、可交付”。任何编码、提交、部署、验收都要按对应门禁执行。

## 编码前门禁
- 已读取 `AGENTS.md`。
- 已读取 `PROJECT_STATE.md`。
- 已读取本次任务相关的 `rules/` 和 `specs/` 文件。
- 已确认当前分支和工作树状态。
- 已明确本次任务是否需要远程部署。
- 已确认是否需要使用 skill；需要时先读取对应 skill 文档。

## 代码提交前门禁
- 改动范围只覆盖本次任务。
- 没有提交密钥、缓存、生成媒体、上传文件、部署压缩包。
- Python 修改已运行必要语法检查。
- 前端/Remotion 修改已至少做静态检查或局部构建检查。
- 已运行 `git diff --check`。
- 文档中没有未解释的占位词。
- 如果改变成片效果，已准备平台生成和抽帧验证计划。

## 远程部署前门禁
- 已更新 `PROJECT_STATE.md`。
- 已提交本地改动。
- 已记录本地分支、提交、提交时间。
- 已确认要同步的文件清单。
- 已确认需要重启哪些服务。
- 已确认不上传 `.env` 私密配置、storage、uploads、cache、dist 临时产物，除非任务明确要求。

## 远程部署后门禁
- 已确认远程部署目录分支和提交。
- 已确认相关 systemd 服务状态。
- 已确认渲染服务健康接口可用。
- 已通过 3003 平台创建新任务。
- 已下载成片。
- 已确认 MP4 有音频流。
- 已抽取关键帧。
- 已记录 job id、输出路径、验证结论到 `PROJECT_STATE.md`。

## 成片验收门禁
- 场景图只有一张且居中。
- 场景图完整展示，没有白框、遮挡、裁切、持续缩放。
- 字幕逐 cue 变化且覆盖完整旁白。
- 音频和字幕无明显提前或滞后。
- 总结关键词 2-4 字，内容是关键词总结，不是字幕截取。
- 总结关键词在分段内依次累计展示，分段结束一起消失。
- 右上角 `心理分享 | 认知突破` 可见。
- 无 `@Sc1火柴人`。
- 整体布局和节奏接近参考视频。

## 文档验收门禁
- 文档默认使用中文。
- 英文术语可保留，但必须解释其项目含义。
- 文档必须包含具体路径、命令、验收条件或决策，不写泛泛建议。
- 更新规则或规格后，要同步更新 `PROJECT_STATE.md`。
